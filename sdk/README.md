# Client libraries

Three libraries, one job: make the piece of code you actually have to write
impossible to get wrong.

StatusHub's integration is a URL change — you point a provider at us and stop
parsing their payload. The only code left on your side is a handler for one
schema, and the only security-critical line in it is the signature check.

That line is the most commonly botched part of any webhook integration.
Somebody compares two hex strings with `==`, which short-circuits on the first
differing byte, and an attacker who can measure the timing can forge a
signature a byte at a time. Nobody notices, because the handler works
perfectly.

```bash
go get github.com/nobledeveloper01/StatusHub/pkg/statushub
npm install @statushub/node
pip install statushub
```

All three are **Apache-2.0**, so integrating needs no lawyer. The server is
BUSL-1.1; the libraries deliberately are not.

## Go

```go
http.Handle("/hooks/statushub", statushub.Handler(secret, func(w http.ResponseWriter, e statushub.Event) {
    switch e.Status {
    case statushub.StatusSuccess:
        ledger.Credit(e.TransactionRef, e.AmountMinor, e.Currency)
    case statushub.StatusUnknown:
        // StatusHub did not recognise the provider's value and refused to
        // guess. e.UnmappedStatus carries what they actually sent.
        review.Queue(e.TransactionRef, e.UnmappedStatus)
    }
    w.WriteHeader(http.StatusOK)
}))
```

## Node

```js
import express from 'express';
import { verifySignature, parseEvent } from '@statushub/node';

// raw, not json — the signature covers the bytes that were sent, and a round
// trip through a parser changes them.
app.post('/hooks/statushub', express.raw({ type: 'application/json' }), (req, res) => {
  if (!verifySignature(req.body, req.headers['x-statushub-signature'], SECRET)) {
    return res.status(401).end();
  }
  handleEvent(parseEvent(req.body));   // one schema, forever
  res.status(200).end();
});
```

## Python

```python
from flask import request
from statushub import verify_signature, parse_event, first_header

@app.post("/hooks/statushub")
def hook():
    # get_data(), not request.json — the signature covers the raw bytes.
    body = request.get_data()
    if not verify_signature(body, first_header(request.headers), SECRET):
        return "", 401
    handle_event(parse_event(body))
    return "", 200
```

## Three things to get right

1. **Hash the raw bytes**, before any JSON parsing. Reordered keys, changed
   whitespace and reformatted numbers all break the signature.
2. **Compare in constant time.** Every library here uses the platform's
   constant-time comparison; if you write your own, use `crypto/subtle`,
   `timingSafeEqual`, or `hmac.compare_digest`.
3. **Check the timestamp.** The digest on a captured delivery stays valid
   forever. Only the five-minute window stops a replay — and the window is
   symmetric, because clocks drift both ways.

During a secret rotation the header carries several `v1=` values and any one
matching is enough, so you rotate on your own schedule rather than
coordinating a cutover.

## How the three stay in agreement

`sdk/fixtures/signature_vectors.json` is generated by the **server's own
signing code**:

```bash
go test ./tests -run GenerateSDKFixtures
```

Every library's test suite verifies against that file. Three implementations
agreeing with each other but not with the server is a real failure mode, and
it is the one this arrangement is designed to make impossible.

The vectors cover the cases worth being sure about: a genuine delivery, two
signatures mid-rotation, a header element the library has never seen, a sender
whose clock runs fast, a replay an hour late, a tampered body, the wrong
secret, and three malformed headers.
